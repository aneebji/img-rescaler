# Contributing to Image Rescaler

Thank you for helping improve Image Rescaler. Useful contributions include reproducible bug reports, accessibility fixes, export reliability improvements, tests, and clear documentation.

## Before you begin

- Search existing [issues](https://github.com/aneebji/img-rescaler/issues) and pull requests to avoid duplicate work.
- For substantial features or architecture changes, open a feature request describing the user problem and proposed behavior before implementing it.
- Small fixes and documentation corrections can go straight to a pull request.
- Follow [SECURITY.md](./SECURITY.md) for vulnerabilities. Do not publish sensitive data or exploit details in a bug report.

## Local setup

Fork the repository, install Node.js 22.12 or newer and npm, then:

```bash
git clone https://github.com/YOUR-USERNAME/img-rescaler.git
cd img-rescaler
npm ci
npm run dev:web
```

Use `npm run dev` for Electron. Desktop development requires a graphical environment. Use a branch with a descriptive name for your change.

## Working in the codebase

- Keep changes focused on one problem and explain the resulting user behavior.
- Follow the existing JavaScript and CSS conventions. Avoid adding a dependency when a small, clear implementation is sufficient.
- Preserve the shared renderer's browser and Electron API contract. Changes to image import, crop coordinates, export options, or progress events should be checked in both adapters.
- Keep image processing local. Any change that sends user data over the network requires an explicit design discussion and clear product disclosure.
- Validate input at processing boundaries. Avoid unsafe HTML construction with file names or other user-controlled values.
- Preserve keyboard access, visible focus, readable contrast, reduced-motion preferences, and small-screen usability.
- Add meaningful regression coverage for behavior changes. Do not include personal images, exported archives, credentials, or generated desktop packages in commits.

The `docs/` directory is generated by `npm run build:pages`; make application changes in source files. Include a rebuilt `docs/` only when your pull request is intended to update the published site, and call that out in the description.

## Verify your change

Run the repository checks:

```bash
npm run check
npm test
npm run build
```

For browser changes, also run the Playwright workflow and export tests. Install the test browser once with `npx playwright install chromium`, then run `npm run test:e2e`. The test configuration starts the development server automatically.

For changes affecting the interface or image pipeline, manually verify the relevant scenarios:

- Import PNG, JPEG, and WebP images, including a transparent image and a filename with spaces.
- Select multiple images and target sizes. Edit one crop, switch away, and verify its composition is retained.
- Export PNG, JPEG, and WebP; inspect dimensions, composition, transparency, and the selected quality behavior.
- Export with and without originals, and check duplicate source names do not overwrite another result.
- Try an unsupported or corrupt file and verify the error is understandable.
- Check light and dark themes, a narrow viewport, and keyboard navigation.
- If changing desktop behavior, test image selection, folder selection, export progress, and opening the result folder in Electron.

State exactly which checks you ran and any environment you could not test. Attach before/after screenshots for visual changes, using images you have permission to share.

## Open a pull request

Use a short title that describes the change. In the description, explain:

1. The problem and how to reproduce it, or the workflow being improved.
2. What users will experience after the change.
3. How you verified it, including relevant browser or operating system details.
4. Any limitations, migration requirements, or follow-up work.

Link related issues and keep unrelated refactors out of the pull request. Be respectful and constructive in reviews; critique the work, not the person.
